# 数学 PDF 入库笔记模板与插件工作流

## 目标

后续上传数学 PDF 后，只参考当前仓库的数学体系，不使用 408 模板。目标是把 PDF 内容整理成 Obsidian 可复习、可检索、可链接的数学笔记：章节基础知识、方法卡、思维导图入口、题目/错题卡、同类题目汇总。

## 笔记类型

- `基础知识`：章节知识点主体，适合定义、定理、公式、性质、例题、易错点。
- `方法`：抽象出通用解题套路，比如“降维法”“补形法”“概率分布四板斧”。
- `思维导图`：每章入口页，通常命名为 `x-0 xxx思维导图.md`，用 `[[链接]]` 和 `![[嵌入]]` 串起知识点、方法、题型。
- `题目`：题目/错题卡，保留 `status`、`method`、`cover`，正文包含“题目 / 复盘 / 举一反三”。
- `同类题目汇总`：用 Dataview 按标签、类型、评分动态汇总方法和题目。
- `补充知识`：用于 PDF 中有价值但不适合放进主线章节的旁支理解、证明或扩展。

## PDF 入库步骤

1. 识别 PDF 属于高数、线代、概率论的哪一章；原始 PDF 不移动、不删除。
2. 提取 PDF 目录、页码范围、知识点、例题、图表；OCR 不清处标记 `待确认`。
3. 先建立或补全 `基础知识` 笔记，保持公式、条件、结论完整。
4. 再抽出可复用的 `方法` 笔记，把“某一题的技巧”升级为“同类题的入口”。
5. 对有价值的题目生成 `题目` 卡；题图放入当前附件路径 `./fig`，正文写复盘和举一反三。
6. 更新本章 `思维导图`，把新知识、方法、题型接到已有网络里。
7. 如某类题目数量足够，新增或更新 `同类题目汇总`，用 Dataview 自动拉取。
8. 最后检查 frontmatter、链接、图片引用、公式渲染、Dataview 查询是否正常。

## 插件使用

- **Templater**：新建基础知识、方法、题目、同类题目汇总时套用模板；题目卡自动按父文件夹加前缀、生成创建日期和封面字段。
- **Dataview**：章节汇总页和同类题目页动态查询，例如按 `type="题目"`、`type="方法"`、`tags`、`rating` 汇总。
- **Obsidian Mind Map NextGen**：把 `x-0 xxx思维导图.md` 当章节复习入口，标题层级就是脑图结构。
- **Paste Image Rename**：PDF 截图、题图、图像公式粘贴后统一命名；当前附件路径是 `./fig`。
- **Mousewheel Image Zoom**：检查题图、教材截图、函数图像时放大查看。
- **Excalidraw**：遇到几何图形、积分区域、线代结构图时，用它重画成可复习图解。
- **Floating TOC**：长章节笔记里快速跳转定义、公式、例题、易错点。
- **Callout Manager**：统一维护提示块风格；数学笔记里优先用 `note`、`tip`、`warning`、`example`、`quote`。
- **Obsidian Git**：如果当前目录是 Git 仓库，每次大批量 PDF 入库前后做版本备份，避免覆盖已有手写补充。
- **OZ Clear Unused Images**：整理完成并确认无误后，再清理未引用图片；不要在入库过程中提前清理。

## 保护规则

- 不使用 408 笔记体系。
- 不默认修改 `.obsidian/`、插件目录、主题配置。
- 不覆盖已有“我的补充”“错题复盘”“手写批注”。
- 多文件大范围整理前先检查 `git status`；如果当前目录不是 Git 仓库，就先说明无法创建 Git 备份提交。
- 新资料和旧笔记冲突时，单独列出冲突点，不直接覆盖。
