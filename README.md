# kaoyan-math-ai

一个面向考研数学一复习的 Obsidian 本地知识库。当前主线是把张宇高数、线性代数、概率论与数理统计(后续还会继续补充包括武忠祥强化、张宇强化等数学资料)的 PDF、逐章 OCR 草稿和章节理解母稿放在同一个仓库里，用双链把章节、概念、方法、例题索引、OCR 高价值图片和错题回流连起来，目标是减少机械抄写，把复习重心放到理解、回顾、复盘和知识连接上。

我的主要目的是建立从电子版资料到可修改填充记忆的电子笔记的工作流。大家可以利用我的工作流自行寻找电子版或者目前自己学习的数学资料去记录笔记！

![README preview](fig/README.png)

## 项目简介

`kaoyan-math-ai` 不是单纯的资料堆放处，而是一个持续迭代的考研数学复习系统：

- 用 Markdown 保存可检索、可链接、可长期维护的数学笔记。
- 用 Obsidian 双向链接串起章节母稿、知识点、方法入口和题型线索。
- 用 `标准数学笔记模板.md` 统一数学章节复习母稿的结构。
- 用 OCR 辅助读取 PDF 和扫描资料，但正式知识内容必须经过逐条理解、归纳和复核，不能只停留在模板骨架。
- 从 OCR 图片资产中精选体系图、流程图、区域图、函数图、公式结构图或关键例题图，并配 `图像精读` 说明它为什么值得看、连接哪些考点、做题时怎么用。
- 用模板文件夹提供手动起稿骨架，而不是把模板填满就当作完成笔记。

如果你想把数学复习资料从“散乱 PDF + OCR 草稿 + 临时笔记”逐步整理成一个可搜索、可回顾、可继续扩展的本地知识库，这个项目就是为这种工作流准备的。

## 当前主线

当前数学笔记的主入口是：

```text
数学笔记/
```

其中每一讲的 `*-标准笔记.md` 是章节级“理解母稿 / 复习母稿”。这些母稿不是批量小卡，也不是空栏目集合，而是先把本章来源、复核边界、考点权重、知识体系、概念区、做题动作、命题信号、例题索引、易错点、反例边界、Dataview、后续链接、错题回流和最小记忆清单整理清楚，再决定是否拆出基础知识、方法、题目或错题卡。

当前已经形成三条数学主线：

| 学科 | 章节入口 | OCR 汇总入口 | 当前产物 |
| --- | --- | --- | --- |
| 高等数学 | `数学笔记/张宇基础30讲/` | `数学笔记/张宇基础30讲/paddleocr/_final/` | 18 篇章节理解母稿 |
| 线性代数 | `数学笔记/张宇-线性代数/` | `数学笔记/张宇-线性代数/paddleocr/_final/` | 7 篇章节理解母稿 |
| 概率论与数理统计 | `数学笔记/张宇-概率论与数理统计/` | `数学笔记/张宇-概率论与数理统计/paddleocr/_final/` | 6 篇章节理解母稿 |

成熟母稿的完成标准是“高知识密度 + 可复习 + 可做题前调用”：每个核心概念要写清本质理解、适用条件、判定方式、易混边界和后续用途；做题动作区要写题型判断路径；命题信号要能指导下手；易错点、反例边界和最小记忆清单要能真正减少误判。

`标准数学笔记模板.md` 是当前数学章节笔记的第一标准。`模版文件夹/` 只作为 Obsidian 手动起稿骨架，主要提供 frontmatter、空栏目、空表格和 Dataview 查询块；如果模板文件夹里的旧栏目和 `标准数学笔记模板.md` 冲突，以 `标准数学笔记模板.md` 为准。

## 适合谁使用

这个仓库比较适合：

- 正在准备考研数，希望系统整理高数、线代、概率论的人。
- 喜欢用 Obsidian、Markdown、双链和 Dataview 做长期复习的人。
- 希望用 AI/OCR 减少机械抄写，把更多时间放到理解和复盘上的人。
- 想参考一套“数学 PDF 入库 -> OCR 草稿 -> 章节理解母稿 -> 拆卡 / 错题回流”的 Obsidian 工作流的人。

它不太适合只想下载一套完整标准答案、直接刷题背题的人。仓库更强调“整理、连接、回顾”的过程。

## 新手快速开始

1. 安装 [Obsidian](https://obsidian.md/) 桌面端。
2. 下载或克隆本仓库到本地。
3. 打开 Obsidian，选择“打开本地文件夹作为仓库”。
4. 选择本项目根目录，也就是包含 `README.md`、`数学笔记/`、`.obsidian/` 的文件夹。
5. 如果 Obsidian 提示是否信任该仓库、是否启用第三方插件，请确认你理解风险后再启用。
6. 打开 `数学笔记/`，从高数、线代或概率论对应讲次的 `*-标准笔记.md` 开始浏览。
7. 新建笔记时优先参考 `标准数学笔记模板.md`；如果只是手动起稿，再使用 `模版文件夹/` 中的模板。

如果你是第一次使用 Obsidian，建议先确认左侧文件列表能看到 `数学笔记/`、`标准数学笔记模板.md`、`模版文件夹/`，再开始配置插件。

## 原生 Markdown 转 PDF 插件

仓库内置了一个桌面端专用插件：

```text
.obsidian/plugins/native-single-pdf-export/
```

插件 ID 是 `native-single-pdf-export`，用途是把单个 Markdown 文件按 Obsidian 原生渲染效果导出为 PDF。后续如果需要把多讲笔记批量转 PDF，Codex 应该枚举每个 `*-标准笔记.md`，逐个调用这个单文件插件；不要重新写 Python、pandoc、HTML 或 Chrome 打印流程来替代 Obsidian 原生导出。

插件支持两种入口：

- 命令面板：`Native PDF Export: Export active Markdown to absolute path`
- URI 调用：

```text
obsidian://native-single-pdf-export?file=<vault-relative-md>&output=<absolute-pdf>&open=false
```

示例：

```text
obsidian://native-single-pdf-export?file=数学笔记/张宇基础30讲/01-第1讲-函数极限与连续/01-第1讲-函数极限与连续-标准笔记.md&output=C:\Users\11832\Desktop\数学资料\01-第1讲-函数极限与连续-标准笔记.pdf&open=false
```

使用注意：

- `file` 使用仓库内相对路径，建议用 `/` 分隔。
- `output` 使用 Windows 绝对路径，且必须以 `.pdf` 结尾。
- 已存在同名 PDF 时默认覆盖，父目录不存在时自动创建。
- 如果刚安装或更新插件后 URI 没反应，重启 Obsidian 后再调用。
- 批量导出完成后，应检查 PDF 数量、文件大小，并尽量读取页数确认文件可解析。

这些图片在最终 OCR 文档中使用 Obsidian 可解析的库内完整路径，例如：

```text
![[数学笔记/张宇基础30讲/paddleocr/_final/01-第1讲-函数极限与连续-assets/example.jpg|550]]
![[数学笔记/张宇-线性代数/paddleocr/_final/02-第2讲-矩阵-assets/example.jpg|550]]
```

正式章节母稿默认每讲至少嵌入 1 张高价值 OCR 图片，除非该讲 OCR 资产确实没有复习价值。图片必须配 `图像精读` 或等价说明，解释“为什么看这张图、它连接哪些考点、做题时怎么用”。不要为了装饰堆图；广告、水印、二维码、低信息截图和无法判断价值的碎片图不进入正式母稿。

不要把 `_final` 文档里的图片写成只相对当前文件的短路径，例如 `![[01-第1讲-函数极限与连续-assets/example.jpg|550]]`，否则 Obsidian 可能会按库根解析并显示为失效图片。完成图片迁移或正式笔记嵌入后，需要检查图片引用能从仓库根定位到真实文件，目标是 `missing_refs=0`。由于仓库图片受 Git LFS 管理，如果看到图片文件内容是 `version https://git-lfs.github.com/spec/v1`，说明那只是 LFS 指针，不是真图片；需要先取得真实 LFS 对象后再打开或迁移。

## OCR 与 AI 笔记工作流

OCR 工具位于：

```text
tools/paddleocr_client.py
tools/paddleocr_README.md
```

推荐流程：

1. 先确认 PDF 来源、讲次、页码范围和是否扫描型资料。
2. 多章节扫描型 PDF 必须先拆章，拆章 PDF 统一进入 `数学笔记/split/<资料名或学科名>/`；不要把整本 PDF 作为正式 OCR 输入。
3. OCR 以拆好的单章 PDF 为输入逐章执行；已有来源正确的逐章 OCR 草稿时优先复用并抽查关键页。
4. OCR 中间结果保留在对应学科的 `paddleocr/_source/` 或任务指定草稿目录，最终汇总入口统一使用 `数学笔记/<学科>/paddleocr/_final/`。
5. 每一讲只保留一个最终 OCR 文档和一个 manifest，图片资产放在同名 `*-assets/` 目录；最终 OCR 文档中用 `<!-- page: N -->` 保留页边界。
6. 不建议直接阅读或双链旧的 `doc_0.md`、`doc_1.md` 分页文件；后续整理优先使用 `_final/<讲名>.md`。
7. 图片会经过过滤：默认删除页眉页脚、二维码、水印、公众号/微信/有机研/45550060 等推广图，保留复杂函数图、流程图、思维导图、区域图、公式结构图和有解释价值的图表。
8. OCR 后处理会保守修复明显畸形公式，例如误包成 `\frac{整条等式}` 的坏 LaTeX；无法确认的符号仍应标记 `待确认`，不能猜。
9. 第一产物是对齐 `标准数学笔记模板.md` 的章节理解母稿，不是批量小卡，也不能只生成空骨架。
10. 成熟母稿必须完成知识密度打磨：章节主线、概念本质、适用条件、判定方式、易混边界、后续用途、做题路径、命题信号、易错反例和最小记忆清单都要能支持复习。
11. 每讲默认至少精选 1 张 OCR 高价值图片嵌入母稿，并配 `图像精读`；如果确实无高价值图，必须在 `待确认` 写明原因。
12. 重要公式尽量改写为 LaTeX；OCR 不清、公式无法确认、图片缺失时，在笔记中标记 `待确认`。
13. 例题题干、选项、图像、答案和复杂公式必须回 PDF 复核后才能写成正式题卡；未复核前只进入典型例题索引表。
14. 小卡只能从章节母稿中拆出；低价值题不机械拆卡，重复题不机械拆卡。

使用 PaddleOCR 时，token 应通过环境变量提供，不要写进脚本、笔记或公开提交记录。

OCR 迁移或重生成后，建议做这些检查：

```text
1. _final/ 下最终 OCR 文档和 manifest 数量是否符合讲次数。
2. 章节母稿是否包含非空的概念理解、做题路径、命题信号、易错点、反例边界和最小记忆清单。
3. 每篇成熟母稿是否至少有 1 个 `图像精读`，或明确写出无图原因。
4. 所有 Obsidian 图片嵌入是否能从仓库根定位到真实文件，要求 `missing_refs=0`。
5. 图片是否为真实 JPEG/PNG/WebP，而不是 Git LFS 指针文本。
6. 正式笔记中是否没有整段搬运 OCR 原文，未复核例题是否仍停留在索引层。
```

## 双链维护规则

- 库内笔记使用 Obsidian wikilink，例如 `[[标准数学笔记模板]]`。
- 章节母稿的短标题应写入 frontmatter `aliases`，让 `[[01-第1讲-函数极限与连续]]` 这类短链接能正常解析。
- 模板里的占位内容不要写成真实 wikilink，避免图谱中出现 `待补充`、`相关方法`、`相关基础知识` 等假节点。
- 删除旧笔记后，不要自动恢复；能明确归属的旧链接改向现有章节母稿，不能确定的写入 `待确认`。
