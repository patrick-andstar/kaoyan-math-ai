# kaoyan-math-ai

一个面向考研数学一复习的 Obsidian 本地知识库。当前主线是把张宇基础 30 讲的 PDF、OCR 草稿和章节理解母稿放在同一个仓库里，用双链把章节、概念、方法、例题索引和错题回流连起来，目标是减少机械抄写，把复习重心放到理解、回顾、复盘和知识连接上。

![README preview](fig/README.png)

## 项目简介

`kaoyan-math-ai` 不是单纯的资料堆放处，而是一个持续迭代的考研数学复习系统：

- 用 Markdown 保存可检索、可链接、可长期维护的数学笔记。
- 用 Obsidian 双向链接串起章节母稿、知识点、方法入口和题型线索。
- 用 `标准数学笔记模板.md` 统一数学章节复习母稿的结构。
- 用 OCR 辅助读取 PDF 和扫描资料，但正式知识内容必须经过逐条理解、归纳和复核。
- 用模板文件夹提供手动起稿骨架，而不是把模板填满就当作完成笔记。

如果你想把数学复习资料从“散乱 PDF + OCR 草稿 + 临时笔记”逐步整理成一个可搜索、可回顾、可继续扩展的本地知识库，这个项目就是为这种工作流准备的。

## 当前主线

当前数学笔记的主入口是：

```text
张宇/张宇基础30讲/
```

其中每一讲的 `*-标准笔记.md` 是章节级“理解母稿 / 复习母稿”。这些母稿不是批量小卡，而是先把本章来源、复核边界、考点权重、知识体系、概念区、做题动作、命题信号、例题索引、易错点、反例边界、Dataview、后续链接、错题回流和最小记忆清单整理清楚，再决定是否拆出基础知识、方法、题目或错题卡。

`标准数学笔记模板.md` 是当前数学章节笔记的第一标准。`模版文件夹/` 只作为 Obsidian 手动起稿骨架，主要提供 frontmatter、空栏目、空表格和 Dataview 查询块；如果模板文件夹里的旧栏目和 `标准数学笔记模板.md` 冲突，以 `标准数学笔记模板.md` 为准。

## 适合谁使用

这个仓库比较适合：

- 正在准备考研数学一，希望系统整理高数、线代、概率论的人。
- 喜欢用 Obsidian、Markdown、双链和 Dataview 做长期复习的人。
- 希望用 AI/OCR 减少机械抄写，把更多时间放到理解和复盘上的人。
- 想参考一套“数学 PDF 入库 -> OCR 草稿 -> 章节理解母稿 -> 拆卡 / 错题回流”的 Obsidian 工作流的人。

它不太适合只想下载一套完整标准答案、直接刷题背题的人。仓库更强调“整理、连接、回顾”的过程。

## 新手快速开始

1. 安装 [Obsidian](https://obsidian.md/) 桌面端。
2. 下载或克隆本仓库到本地。
3. 打开 Obsidian，选择“打开本地文件夹作为仓库”。
4. 选择本项目根目录，也就是包含 `README.md`、`张宇/`、`.obsidian/` 的文件夹。
5. 如果 Obsidian 提示是否信任该仓库、是否启用第三方插件，请确认你理解风险后再启用。
6. 打开 `张宇/张宇基础30讲/`，从对应讲次的 `*-标准笔记.md` 开始浏览。
7. 新建笔记时优先参考 `标准数学笔记模板.md`；如果只是手动起稿，再使用 `模版文件夹/` 中的模板。

如果你是第一次使用 Obsidian，建议先确认左侧文件列表能看到 `张宇/`、`标准数学笔记模板.md`、`模版文件夹/`，再开始配置插件。

## 图片与附件管理

仓库附件路径配置为：

```text
./fig
```

推荐规则：

- 每个章节或笔记目录下可以有自己的 `fig/` 文件夹。
- 粘贴图片时用 Paste image rename 顺手改成可读文件名。
- 图片引用使用 Obsidian 嵌入语法；README 示例不写成真实双链，避免图谱出现占位图片节点。
- 不要随意移动图片目录，否则已有笔记里的图片链接可能失效。
- 定期用 Clear Unused Images 检查无引用图片，但清理前建议先备份。

PaddleOCR 汇总草稿的图片资产集中放在：

```text
张宇/张宇基础30讲/paddleocr/_final/<讲名>-assets/
```

这些图片在最终 OCR 文档中使用 Obsidian 可解析的库内完整路径，例如：

```text
![[张宇/张宇基础30讲/paddleocr/_final/01-第1讲-函数极限与连续-assets/example.jpg|550]]
```

不要把 `_final` 文档里的图片写成只相对当前文件的短路径，例如 `![[01-第1讲-函数极限与连续-assets/example.jpg|550]]`，否则 Obsidian 可能会按库根解析并显示为失效图片。由于仓库图片受 Git LFS 管理，如果看到图片文件内容是 `version https://git-lfs.github.com/spec/v1`，说明那只是 LFS 指针，不是真图片；需要先取得真实 LFS 对象后再打开或迁移。

## OCR 与 AI 笔记工作流

OCR 工具位于：

```text
tools/paddleocr_client.py
tools/paddleocr_README.md
```

推荐流程：

1. 先确认 PDF 来源、讲次、页码范围和是否扫描型资料。
2. 对扫描型 PDF 做 OCR；已有可用 OCR 草稿时优先复用并抽查关键页。
3. OCR 中间结果保留在 `张宇/张宇基础30讲/paddleocr/` 或任务指定草稿目录。
4. 当前张宇基础 30 讲的 OCR 汇总入口是 `张宇/张宇基础30讲/paddleocr/_final/`，每一讲对应一个最终 OCR 文档，文内用 `<!-- page: N -->` 保留页边界。
5. 不建议直接阅读或双链旧的 `doc_0.md`、`doc_1.md` 分页文件；后续整理优先使用 `_final/<讲名>.md`。
6. 图片会经过过滤：默认删除页眉页脚、二维码、水印、公众号/微信/有机研/45550060 等推广图，保留复杂函数图、流程图、思维导图和有解释价值的图表。
7. OCR 后处理会保守修复明显畸形公式，例如误包成 `\frac{整条等式}` 的坏 LaTeX；无法确认的符号仍应标记 `待确认`，不能猜。
8. 第一产物是对齐 `标准数学笔记模板.md` 的章节理解母稿，不是批量小卡。
9. 重要公式尽量改写为 LaTeX；OCR 不清、公式无法确认、图片缺失时，在笔记中标记 `待确认`。
10. 例题题干、选项、图像、答案和复杂公式必须回 PDF 复核后才能写成正式题卡。
11. 小卡只能从章节母稿中拆出；低价值题不机械拆卡，重复题不机械拆卡。

使用 PaddleOCR 时，token 应通过环境变量提供，不要写进脚本、笔记或公开提交记录。

OCR 迁移或重生成后，建议做三类检查：

```text
1. _final/ 下最终 OCR 文档数量是否符合讲次数。
2. 所有 Obsidian 图片嵌入是否能从仓库根定位到真实文件。
3. 图片是否为真实 JPEG/PNG/WebP，而不是 Git LFS 指针文本。
```

## 双链维护规则

- 库内笔记使用 Obsidian wikilink，例如 `[[标准数学笔记模板]]`。
- 章节母稿的短标题应写入 frontmatter `aliases`，让 `[[01-第1讲-函数极限与连续]]` 这类短链接能正常解析。
- 模板里的占位内容不要写成真实 wikilink，避免图谱中出现 `待补充`、`相关方法`、`相关基础知识` 等假节点。
- 删除旧笔记后，不要自动恢复；能明确归属的旧链接改向现有章节母稿，不能确定的写入 `待确认`。
